# Токенизация русско-английских технических обозначений

Данные и код к статье В. Качалова и Н. Г. Ферсман «Токенизация русско-английских
технических обозначений: сравнение с сопоставленной бытовой лексикой».

Вопрос работы такой: русские технические термины занимают больше токенов, чем английские,
но больше ли этот разрыв, чем у обычных бытовых слов той же длины и структуры? Для этого
159 пар терминов сравниваются с 131 сопоставленной бытовой парой в токенизаторах `o200k_base`,
`cl100k_base` и `Qwen2.5-7B`. Модели не запускаются, считается только разбиение текста на токены.

## Что где лежит

| Папка | Содержимое |
|---|---|
| `expansion_wipo_v1/data/` | итоговая выборка v1.2: термины, контроль, пары, термины без пары |
| `expansion_wipo_v1/candidates/` | кандидаты из WIPO Pearl и решения по ним |
| `expansion_wipo_v1/plan/` | дополнение к протоколу и `FREEZE.json` с контрольными суммами |
| `expansion_wipo_v1/results/` | результаты по срезам: `new`, `control`, `combined`, `sensitivity` |
| `expansion_wipo_v1/reports/` | отчёт о расширении выборки и построчный аудит понятий |
| `data/`, `results/` | первая фаза: 90 понятий и их контроль |
| `src/tok_pilot/` | подсчёт токенов, метрики, кластерный бутстрэп |
| `scripts/` | запуск расчётов и тесты |
| `article/` | таблицы и рисунки статьи |

Основные файлы: `concepts_combined.csv` (159 терминов), `matching_pairs_combined.csv` (131 пара),
`unmatched_technical.csv` (28 терминов, которым не нашлась пара). Протокол исследования лежит в
корне: `protocol_ru_en_tokenization.md`.

## Как повторить расчёт

Нужен Python 3.12: для `tiktoken==0.7.0` под 3.13 нет готовых колёс.

```bash
python -m venv .venv
source .venv/bin/activate    # Windows: .venv\Scripts\activate
pip install -r requirements.lock

python scripts/test_counting.py
python scripts/test_control.py
python scripts/test_expansion.py
python scripts/run_expansion.py
```

`run_expansion.py` заново токенизирует выборку и пересчитывает оценки (5000 повторов бутстрэпа,
seed 20260918). Результат пишется в `expansion_wipo_v1/results/`. При первом запуске скачиваются
кодировки `tiktoken` и токенизатор Qwen, поэтому нужен интернет. Снимок Qwen зафиксирован в
`manifest.json`, в ревизии `acbd9653`.

Рисунки и таблицы статьи собирает `scripts/build_article_assets.py`, ему нужен ещё
`requirements_figures.lock`.

## Чего здесь нет

Нет сырых ответов WIPO API и исходных PDF производителей, поэтому отбор кандидатов с нуля из этой
копии не запустится. Таблицы, которые получились на его выходе, лежат в репозитории, их суммы
SHA-256 записаны в `FREEZE.json`. Для повторного опроса WIPO нужны свои ключи: они читаются из
`src/api.env`, формат показан в `src/api.env.example`.

## Отбор и фиксация выборки

Разбор отбора по 69 новым понятиям и причины исключений, например пары spool valve / золотник, лежат в
`expansion_wipo_v1/reports/ОТЧЁТ_РАСШИРЕНИЕ.md`. Редакция v1.2 зафиксирована после просмотра
предварительных результатов, это записано в `FREEZE.json` и в статье.

Вывод относится к названиям приборов и компонентов промышленной автоматизации и к длине в токенах.
Качество ответов моделей здесь не измерялось.
